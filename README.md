# 考研学习进度档案

用 Markdown 记录数学三、英语一、政治和 431 专业课的学习事实，让不同 AI 工具都能接着同一份进度继续工作。文件保存在自己的 GitHub 仓库里，也可以下载到本地，用 VS Code、Cursor 或任意文本编辑器维护。

## 当前使用方式

目前只在 Windows 工作。**你每天直接告诉助手实际学习进度，助手负责整理文件并提交上传 GitHub。** 不需要先把反馈整理成表格，也不需要每天手动操作 Git；跨设备同步和桌面备份暂不安排。

## 从这里开始

1. 查看 [CURRENT.md](CURRENT.md)，将目标届别、院校、资料和各科起点中需要补充的信息告诉助手。未知信息保留“待填写”。
2. 学习结束后发来实际表现；助手在当天日记中记录事实，更新 [MISTAKES.md](MISTAKES.md)、专项索引及总览。
3. 助手上传后反馈整理结果，你可以查看 GitHub 上的文件，有遗漏或错误再告诉助手更正。

已导入你提供的[英语一冲刺档案](subjects/ENGLISH.md)：客观题 50/60；混合模拟总分 75.5/100，含非官方主观估分。数学三、政治和 431 仍待填写。原始文件保存在 `sources/`；导入日期不代表实际测试日期，建议和估分不会记成完成事实。

此前准备的[本地与双机同步说明](SYNC.md)保留备用，目前不需要执行。

## 文件怎么分工

```text
kaoyan/
├── README.md              使用说明
├── CURRENT.md             当前状态、证据和下一步
├── MISTAKES.md            错题与薄弱点的复测记录
├── AI_PROMPTS.md          可复制到各类 AI 的指令
├── AGENTS.md              仓库内 AI 助手的维护规则
├── SYNC.md                本地与双机同步说明（备用）
├── subjects/
│   └── ENGLISH.md         英语一诊断、目标与后续训练索引
├── sources/
│   └── 2026-10-11-考研英语一冲刺进度档案.md  上传原档备查
├── daily/
│   └── 2026-10-11.md       历史英语诊断导入；之后一天一份
└── templates/
    └── DAILY.md           每日记录模板
```

`daily/` 保存事实，`MISTAKES.md` 跟踪问题，`CURRENT.md` 汇总最新状态；`subjects/` 提供专项索引，`sources/` 保存导入原档以便追溯。原档中的判断、估分和计划需分别标注，说明和模板不算学习证据。

## 每天怎么用

用平常说话的方式告诉助手即可，重点包括实际日期、学习材料、独立作答情况、用时和主要问题。补录历史进度时注明是哪一天。可以参考以下格式，只写当天涉及的科目：

```text
日期：……
数学三：学了什么，做了多少题、对了多少，用时及错因。
英语一：材料与题型，结果或评分来源，是否用了提示及主要问题。
政治：内容、练习表现及遗漏要点。
431：章节、练习表现及问题。
下一次想做：……
```

题量、时间记不清时直接说明，不必为了填满字段而猜测。助手收到实际进度后会按“日记 → 错题 → 专项索引与总览”的顺序更新，检查后提交推送，并反馈结果。计划不会记成已经完成。

### 手动记录（可选）

**开始前，约 30 秒：** 把 [每日模板](templates/DAILY.md) 复制为 `daily/YYYY-MM-DD.md`，将标题日期替换为当天日期，写下优先任务和完成标准。同一天继续补充同一个文件。

**结束后，约 3–5 分钟：** 只填写今天学习的科目，记录材料、独立作答表现、用时、错误原因和明天第一件事。未学习的科目写“未学习”；不清楚的数据留“待填写”，不要用 `0` 代替缺失数据。完成填写后再把“记录状态”改为“已填写”或“部分填写”。

发现错题时，在 `MISTAKES.md` 建条目，关联当日日记；更新总览时，在 `CURRENT.md` 加上证据链接。历史日记保留原貌，补录或更正需注明时间和原因。

**每周一次，约 10 分钟：** 使用 [每周复盘指令](AI_PROMPTS.md#每周复盘)，查看近七天的日记和复测结果，调整总览与下一周优先任务。需要留存的复盘结论可追加到复盘当天的日记；不要覆盖已有内容。

## 什么样的记录有用

- **数学三：** 区分看懂解析和独立解出，记录题型、正确题数、用时及错误原因。
- **英语一：** 阅读、完形等客观题记录独立正确率；翻译和写作记录文本、评分依据与具体反馈，主观估分注明来源。
- **政治：** 选择题记录错因；简答或材料题记录独立回忆的要点、遗漏与评分依据。
- **431 专业课：** 按目标院校的大纲和参考书记录，计算题、简答题和论述题分别评估。

题量统计采用：总题数 = 正确 + 错误 + 未作答。独立正确率 = 独立正确题数 ÷ 独立测试总题数，未作答计入分母；同一次练习中看答案后重做，不计入该次独立正确题数。总题数为 0 或未知时不计算正确率。主观题没有评分依据时，不强行转换为正确率。

掌握状态统一使用：

| 状态 | 判断依据 |
| --- | --- |
| 尚未验证 | 没有足够的独立练习或测试证据；不等同于不会 |
| 尚未掌握 | 已有证据显示不能达到当前任务的完成标准 |
| 部分掌握 | 有独立完成证据，但某些题型、速度或复测尚未达标 |
| 已掌握 | 独立测试达到事先设定的标准，并有不同日期的复测支持 |

完成标准由你按题型和阶段设定，可以调整。一次做对、听完课或读完书，不自动视为已掌握；新的复测结果也可以下调原有判断。

## 怎么交给不同 AI 接着用

在 Cursor 或 Codex 中打开整个仓库，使用 [AI_PROMPTS.md](AI_PROMPTS.md) 的指令让助手读取并维护文件。`AGENTS.md` 为支持该文件的工具提供规则；其他工具可以手动附上它，或粘贴通用指令。

在普通 ChatGPT 聊天中，上传 `CURRENT.md`、`MISTAKES.md` 和最近几天的日记，再发送通用指令。只提供电脑上的路径不能让网页聊天自动读取本地文件。AI 更新文件后，检查差异，确认计划没有被记成完成、成绩没有被猜测。

## 保存与备份

日常整理和上传由助手完成。你也可以自行在 GitHub 页面上编辑，或在本地用编辑器和 Git。手动提交时先检查改动，例如：

```bash
git status --short
git diff
git add CURRENT.md MISTAKES.md daily/
git commit -m "更新学习记录"
git push
```

首次提交说明和模板时也需要将这些文件加入暂存区。仓库提供版本历史，建议另外定期下载或复制一份备份。公开仓库中的记录会对外可见，填写学习事实时避免加入身份证号、联系方式或账号凭据。
